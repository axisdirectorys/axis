<p data-importer="text" align="left">Axis is an experimental digital currency that enables instant payments to<br>anyone, anywhere in the world. Axis uses peer-to-peer technology to operate<br>with no central authority: managing transactions and issuing money are carried<br>out collectively by the network. Axis Core is the name of open source<br>software which enables the use of this currency. (Forked from Litecoin & Bitcoin)<br><br>For more information, as well as an immediately useable, binary version of<br>the Axis Core software, see [https://www.axis.directory](https://www.axis.directory).<br><br>License<br>-------<br><br>Axis Core is released under the terms of the MIT license. See [COPYING](COPYING) for more<br>information or see https://opensource.org/licenses/MIT.<br><br>Development Process<br>-------------------<br><br>The `master` branch is regularly built (see `doc/build-*.md` for instructions) and tested, but it is not guaranteed to be<br>completely stable. [Tags](/tags) are created<br>regularly from release branches to indicate new official, stable release versions of Axis Core.<br><br>The https://github.com/axis-project/gui repository is used exclusively for the<br>development of the GUI. Its master branch is identical in all monotree<br>repositories. Release branches and tags do not exist, so please do not fork<br>that repository unless it is for development reasons.<br><br>The contribution workflow is described in [CONTRIBUTING.md](CONTRIBUTING.md)<br>and useful hints for developers can be found in [doc/developer-notes.md](doc/developer-notes.md).<br><br>The developer [mailing list](https://groups.google.com/forum/#!forum/axis-dev)<br>should be used to discuss complicated or controversial changes before working<br>on a patch set.<br><br>Developer IRC can be found on Freenode at #axis-dev.<br><br>Testing<br>-------<br><br>Testing and code review is the bottleneck for development; we get more pull<br>requests than we can review and test on short notice. Please be patient and help out by testing<br>other people's pull requests, and remember this is a security-critical project where any mistake might cost people<br>lots of money.<br><br>
### Automated Testing<br><br>Developers are strongly encouraged to write [unit tests](src/test/README.md) for new code, and to<br>submit new unit tests for old code. Unit tests can be compiled and run<br>(assuming they weren't disabled in configure) with: `make check`. Further details on running<br>and extending unit tests can be found in [/src/test/README.md](/src/test/README.md).<br><br>There are also [regression and integration tests](/test), written<br>in Python, that are run automatically on the build server.<br>These tests can be run (if the [test dependencies](/test) are installed) with: `test/functional/test_runner.py`<br><br>The Travis CI system makes sure that every pull request is built for Windows, Linux, and macOS, and that unit/sanity tests are run automatically.<br><br>
### Manual Quality Assurance (QA) Testing<br><br>Changes should be tested by somebody other than the developer who wrote the<br>code. This is especially important for large or high-risk changes. It is useful<br>to add a test plan to the pull request description if testing the changes is<br>not straightforward.<br><br>Translations<br>------------<br><br>We only accept translation fixes that are submitted through [Bitcoin Core's Transifex page](https://www.transifex.com/projects/p/bitcoin/).<br>Translations are converted to Axis periodically.<br><br>Translations are periodically pulled from Transifex and merged into the git repository. See the<br>[translation process](doc/translation_process.md) for details on how this works.<br><br>**Important**: We do not accept translation changes as GitHub pull requests because the next<br>pull from Transifex would automatically overwrite them again.<br># a</p>
